Dealer Ops 车行管理、CRM 与 OMVIC 广告合规平台

1项目概述

Dealer Ops 是一个多租户车行管理平台。唯一的平台管理员负责开通车行并为车行员工发放登录账号。一个车行可以有多个账号（每位员工一个），所有账号共享该车行的同一份数据。

系统包含三个相互关联的业务模块：车辆管理（DMS）、客户关系管理（CRM）和广告合规检查。三者是同一后端、同一数据库之上的三个前端入口，不是三个独立应用。广告检查直接读取 DMS 中的车辆数据和车行资料，无需重复录入。

2范围

本次交付范围

  • 多租户：车行之间数据隔离，管理员看不到任何业务数据
  • DMS：规格说明书中的车辆字段；VIN 车行内唯一；售出日期与价格成对录入；售出后锁定采购字段
  • CRM：姓名、邮箱、电话、住址；关联本车行车辆；一车一客户
  • 广告合规检查：固定规则清单 + 真实 AI 审查；通过后可标记 Ready 并导出 TXT
  • 审计：DMS/CRM 每次变更记录操作人、动作、时间
  • 只读 AI 助手：查询本车行数据，不写库
  • 登录：管理员下发用户名/密码，角色仅 Platform.Admin / Dealer.User
  • 网关：浏览器只能经 Gateway 访问后端

明确不做

  • 线索管理、跟进任务、销售漏斗
  • 维修工单、整备流程、归档状态
  • 买家网站、公开库存页、询价表单
  • KPI 仪表盘、CSV 导入
  • 第三方广告平台自动发布、支付、合同
  • Image Studio、OCR、VIN 解码
  • 里程、颜色、燃料、库存号、标价等规格外字段
  • 消息队列、第二数据库、向量库
  • 限流配额、吞吐 SLO、PIPEDA 保留策略

课堂演示主线：两个车行、各一名员工互相隔离；管理员调用车辆接口被拒；缺价格或金融广告缺 APR 时被拦截；一条真实广告走真实模型审查；改价后旧的检查结果不能导出。

3.4 账号生命周期

管理员创建车行 → 管理员绑定员工（用户名 + 临时密码 → 车行） → 员工登录 → 访问本车行数据 ↓ 管理员解绑 → 员工再调用业务接口 → 403
  • 账号移除后，其历史审计记录保留，“操作人”不能丢失。
  • 车行最后一个账号被移除后，车行数据仍保留，可再绑定新账号。
  • 重新绑定已解绑的用户视为重新激活：同一车行复用原绑定记录，账号不新建；改绑到其他车行会新增一条绑定记录；重新绑定时会重设临时密码。

4.2 车辆状态

[新建] ──► IN_STOCK 在库 ──（同时录入售出日期 + 售出价格）──► SOLD 已售

  • 状态由服务端推导：两个售出字段都有值即 SOLD，否则 IN_STOCK。
  • 本版本不支持撤销售出（退车）。

4.4 边界情况

  • 年份 = 当前年份 + 1（提前发布的车型年）允许，+ 2 拒绝。
  • 采购成本为 0（如置换抵扣）允许。
  • 售价低于成本允许，不拦截。
  • IRREPARABLE 车辆可以录入和售出（拆件出售），但广告必须如实披露车况。

5CRM 客户管理

每位客户一条记录，购车记录关联回 DMS 车辆。产品简介中的“线索与客户生命周期管理”已被范围基线排除，CRM 只做四个字段加车辆关联。

5.1 字段

#字段代码必填校验规则
1姓名name✓1–100 字符
2邮箱email✓邮箱格式，≤ 254 字符，存小写
3电话phone✓7–20 位数字，允许 + - ( ) 和空格，总长 ≤ 40 字符
4住址homeAddress✓1–300 字符，单个文本框
5已购车辆linkedVehicles（响应字段，经 /customers/{id}/vehicles 关联）—多选关联本车行 DMS 车辆
说明：“已购车辆”在规格说明书中位于必填标题下但没有星号，按可选处理，因为客户可能还未购车（见 Q-03）。

5.2 关联规则

  • 客户 : 车辆 = 1 : N（一位客户可买多辆车）。
  • 车辆 : 客户 = 1 : 0..1（一辆车最多属于一位客户）。
  • 只能关联同一车行的车辆；在库或已售、尚未关联的车辆都可以关联。
  • 已售车辆的关联不能解除（销售记录不可抹掉）。

5.4 典型流程

销售新建客户 → 在客户详情点“关联车辆” → 选择未关联车辆 → 保存 → 在 DMS 录入售出日期 + 售出价格 → 车辆变为 SOLD，关联被锁定

6广告合规检查

广告发布前，系统按 OMVIC（安大略汽车经销商监管机构）的披露要求检查广告文案，标出缺失项。课程交付采用范围基线勘误 3–4 规定的简化规则：BLOCK 为硬性拦截，阻止 Ready 和导出；REVIEW 为提示，不阻止。

交付边界：“发布”= 标记 Ready + 导出 TXT，不对接外部平台，不建买家页面。检查只读取标题 + 正文、DMS 车辆数据和车行公开资料；不新增车辆字段，不收集销售员勾选答案。文案中完全没提到的既往用途或保修无法推断，这是已接受的演示限制。

6.1 广告输入

  • 选择本车行车辆；一辆车一条广告。
  • 标题、正文为可编辑文本；空草稿可保存但不能通过检查。
  • 广告类型：CASH 现金 / FINANCE 金融 / LEASE 租赁。媒介：ONLINE 线上 / RADIO_TV_BILLBOARD 广播电视广告牌。

6.2 规格说明书原始要求（PDF §5）

适用范围必须披露
所有广告车行注册名称与联系方式；既往用途（警车/应急车、出租车/豪华轿车、按日租赁/日租车，如适用）；新/旧状态与年份；延保条款（如提供）；价格；车况（认证 / 现状 / 不适合上路 / 无法修复）
出现利率或付款额的金融广告APR（与付款额同等醒目）；贷款期限；现金价 / 借贷成本。例外：广播、电视、广告牌无需与利率并列展示这些信息。
租赁广告声明是租赁；期限；月供金额；APR；首付金额；超里程费（仅当年度里程额度低于 20,000 km 时需要）

6.5 检查流程与状态

保存草稿 → 点击“检查” ├─ 命中任一 BLOCK 规则 ──────────► BLOCKED（跳过 AI，HTTP 200） └─ 无 BLOCK ──► 调用真实 AI（15 秒超时） ├─ 成功 ──────► PASSED（保留 REVIEW 提示和 AI 意见） └─ 超时/出错 ──► AI_UNAVAILABLE（公开接口 502，绝不显示通过） 检查前：NEEDS_AI 已通过后修改广告或车况 ──► STALE 未通过时修改广告 ──► 回到 NEEDS_AI PASSED 且版本一致 ──► 可“标记 Ready”并“导出 TXT”
  • PASSED 表示演示规则的硬性项通过且 AI 正常响应，不代表法律意义上的合规批准，结果中可能仍有提示项。
  • AI 意见不否决 Ready。
  • 触发失效的修改：广告标题、正文、类型、媒介（含正文中改价），以及车辆车况。其他车辆或车行资料修改不触发失效。
  • Ready / 导出要求 PASSED 且内容版本一致，否则返回 NOT_PASSED / CHECK_STALE。
