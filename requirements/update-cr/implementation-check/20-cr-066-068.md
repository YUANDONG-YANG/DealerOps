## CR-066

**Statement:** The dealership shop page should let a visitor search for dealerships and should show each dealership's address and some contact information.

**Status:** implemented

**Place named:** Home page > shop vehicles (`/shop`, `DealerDirectory` in `frontend/react/src/pages/ShopPage.tsx`). The document does not name the search fields or which contact values count as “some.”

**Present:**

- `ShopPage` renders `DealerDirectory` when the route has no `:dealer` param. `frontend/react/src/router.tsx` maps `/shop` to `ShopPage`.
- `DealerDirectory` loads the directory with `listPublicDealers` (`frontend/react/src/api/publicDealers.ts`), which calls `GET /api/v1/catalog/dealers`.
- A search box (`aria-label` “Search dealerships”, placeholder “Search by dealership name or city”) filters the loaded list in the client. The match text is `legalName` plus `contactAddress`, case-insensitive substring. A miss shows “No dealerships match your search.”
- Each card links to `/shop/{slug}` and, when the value is non-empty, renders `contactAddress`, `contactPhone`, and `contactEmail`.
- `PublicDealer` in `publicDealers.ts` declares those three contact fields.
- `PublicDealerController.Dealers` (`backend/dotnet/DealerOps.Core/Catalog/PublicDealerController.cs`) selects `ContactPhone`, `ContactEmail`, and `ContactAddress` from active dealerships and returns them on `PublicDealerOption`. There is no search query parameter; the list is ordered by legal name.

**Missing:** Nothing the statement requires. The source leaves the search key and the contact fields unnamed; the code uses name and address for search, and shows address, phone, and email on the card.

## CR-067

**Statement:** The dealership buyer site should have a back button and a way to search that dealership's inventory for a specific vehicle.

**Status:** implemented

**Place named:** Home page > shop vehicles > click any dealership (`/shop/:dealer`, `DealerInventory` in `frontend/react/src/pages/ShopPage.tsx`). The source cuts off at “vehicl” and does not name the back destination or the match fields.

**Present:**

- `frontend/react/src/router.tsx` maps `/shop/:dealer` to `ShopPage`. `ShopPage` renders `DealerInventory` when `useParams` has `dealer`.
- Back control: `DealerInventory` renders a link “← Back to dealerships” to `/shop`. The shop header (`ShopHeader`) also has a “Dealerships” link to `/shop`.
- Inventory comes from `buyerSiteApi.inventory` (`frontend/react/src/api/buyerSite.ts`), `GET /api/v1/public/dealers/{dealer}/inventory`. `BuyerSiteController.Inventory` delegates to `BuyerSiteService.Inventory` (`backend/dotnet/DealerOps.Core/BuyerSite/BuyerSiteService.cs`), which returns `PublicInventory` (`backend/dotnet/DealerOps.Core/BuyerSite/Dto/PublicInventory.cs`): contact card plus `PublicVehicle` rows (`ModelYear`, `Make`, `Model`, and the other public listing fields). No search query parameter.
- When the dealership has at least one listed vehicle, `DealerInventory` shows a search box (`aria-label` “Search this dealership's vehicles”, placeholder “Search by make, model or year”). Each word must occur in `{modelYear} {make} {model}`. A miss shows “No vehicles match your search.”

**Missing:** Nothing the statement requires. Title, color, body type, and ad body are on `PublicVehicle` and are not part of the search text. VIN is not on that payload. The statement does not name those fields.

## CR-068

**Statement:** While asking about a vehicle, the character limit should become visible as the text gets closer to that limit.

**Status:** implemented

**Place named:** Home page > Shop vehicles > click on any dealership > Ask about this vehicle. The document does not state the limit or the “closer” threshold.

**Present:**

- `DealerInventory` opens `FormDrawer` titled “Ask about this vehicle” from the button of the same name.
- `INQUIRY_MESSAGE_MAX` in `ShopPage.tsx` is 1000. The message `textarea` (`id` `inquiry-message`) sets `maxLength` to that constant.
- `messageLeft` is `1000 - form.message.length`. When `messageLeft <= 50`, the drawer shows “{messageLeft} of {INQUIRY_MESSAGE_MAX} characters left” (`aria-live="polite"`). The line stays hidden while more than 50 characters remain.
- The same ceiling is on the server: `InquiryRequest.Message` (`backend/dotnet/DealerOps.Core/BuyerSite/Dto/InquiryRequest.cs`) has `[MaxLength(1000)]` with the error “Message must be at most 1000 characters.” `BuyerSiteController.Inquire` accepts that body. `buyerSiteApi.inquire` posts it to `POST /api/v1/public/dealers/{dealerId}/inquiries`.

**Missing:** Nothing the statement requires. The source does not define the number or the threshold; the code uses the existing 1000-character message rule and shows the remaining count from 50 characters left through zero.
