## CR-029

**Statement:** The DMS Make and Model boxes should be removed because search by VIN, make, or model already covers them.

**Status:** implemented

**Place named:** DMS search. The source names the “Make” and “Model” boxes and the “Search VIN, make, or model” box. It does not name a route. The screen is `DmsPage` in `frontend/react/src/pages/DmsPage.tsx`.

**Present:**

- `Filters` in `DmsPage.tsx` is `q`, `modelYear`, `status`, `condition`, `bodyType`, and `openWorkOrdersOnly`. A comment above it says the search box covers make and model, so there are no separate make and model filters.
- The filter row renders `SearchSuggest` with placeholder and `aria-label` “Search VIN, stock #, make or model”, then a Year input, Status, Condition, Body type, and “Open work orders only”. There is no Make select and no Model select.
- `DmsPage` `load` calls `vehiclesApi.list` with that filter object. `vehiclesApi.list` in `frontend/react/src/api/vehicles.ts` sends `make` or `model` only when the caller passes them. `DmsPage` does not.
- `VehicleService.List` (`backend/dotnet/DealerOps.Core/Vehicle/VehicleService.cs`) still matches `q` with `EF.Functions.Like` on `Vin`, `Make`, and `Model` (and stock number; see CR-031).

**Missing:** Nothing the statement requires. Make and Model remain on the Add/Edit vehicle form (`purchaseFields` keys `make` and `model` in the same page). The removal note says stored make and model are not dropped. `VehicleController.List` still accepts query `make` and `model`, and `VehicleService.List` still applies them as case-insensitive exact filters. The DMS page does not show those boxes or send those parameters.

## CR-030

**Statement:** The DMS Year box should become a box the user can type in.

**Status:** implemented

**Place named:** The “Year” box in DMS. The source says the box lists many years. It does not say what a typed value must match. The screen is the filter row in `DmsPage`.

**Present:**

- The Year control is `<input className="input" type="number" inputMode="numeric">` with `placeholder` and `aria-label` “Year”, bound to `drafts.modelYear`. It is not a `<select>`.
- `modelYear` is a text filter (`TextFilters`). A draft is copied onto `filters` after a 350 ms pause, or immediately on Enter (`applySearch`) and on Search.
- `vehiclesApi.list` sends `modelYear` when it is non-empty. `VehicleController.List` binds `[FromQuery] int? modelYear`. `VehicleService.List` keeps rows where `ModelYear` equals that integer.

**Missing:** Nothing the statement requires. The Add/Edit “Model year” field in the same drawer is still a `<select>` (`formYearOptions`). That control is the model-year dropdown in the next inventory item, not this Year filter. A typed value is an exact year, not a prefix or a range. The source does not ask for either.

## CR-031

**Statement:** DMS should gain a search by stock number.

**Status:** implemented

**Place named:** DMS. The source says “adding a box to be able to search based on Stock #.” It does not say exact versus partial, or whether the box is separate from VIN / make / model search. `02-new-capabilities.md` §5.3 says list search `q` already matches stock number and that a separate box is unspecified.

**Present:**

- The DMS search field placeholder and `aria-label` are “Search VIN, stock #, make or model” (`DmsPage`).
- Typing updates `drafts.q`, which becomes `filters.q` and is sent as query `q` by `vehiclesApi.list`.
- `VehicleService.List` matches `q` when `Vin`, `Make`, or `Model` contains it, or when `StockNumber` is not null and contains it (`EF.Functions.Like`).
- Suggestion rows include `stockNumber` in the hint. Choosing a suggestion sets `q` to that row’s `vin` (`value: v.vin`), which still selects that vehicle.
- The inventory table has a Stock # column (`columns` key `stockNumber`). That is display and sort, not the search box.

**Missing:** Nothing the statement requires. There is no Stock #-only input. `Filters` has no stock-number property, and `VehicleController.List` has no stock-number query parameter. `dealer-platform/openapi.yaml` `listVehicles` still describes `q` as “Substring of VIN / make / model” and does not mention stock number. Runtime matching is in `VehicleService.List`, which does include `StockNumber`.

## CR-032

**Statement:** The Add Vehicle make dropdown should be split into major brands and every brand, in the manner of Autotrader.

**Status:** implemented

**Place named:** The Add Vehicle make dropdown. The source says two sections, major brands and every brand, similar to Autotrader. It does not name the major brands. `08-api-and-integrations.md` §2.6 says grouping is client-side and that Autotrader is a layout reference, not an integration.

**Present:**

- The Add vehicle drawer is `FormDrawer` in `DmsPage` (title “Add vehicle” when `edit` is unset). The same form is used for “Edit vehicle”.
- On load, `catalogApi.makes` (`frontend/react/src/api/catalog.ts`) calls `GET /api/v1/catalog/makes`. `VehicleCatalogController.Makes` returns `VehicleCatalogService.MakesAsync`: one alphabetical list of vPIC car and MPV makes. The API does not group them.
- `groupMakes` in `frontend/react/src/vehicleRules.ts` splits that list. `POPULAR_MAKES` is a fixed list of 19 names (Toyota, Honda, Ford, Chevrolet, Nissan, Hyundai, Kia, Mazda, Subaru, Volkswagen, Jeep, Ram, GMC, Dodge, Tesla, BMW, Mercedes-Benz, Audi, Lexus). Names present in the catalog, compared ignoring case, become `popular` in that order. `all` is the catalog list unchanged.
- The Make `<select>` renders an `optgroup` “Popular makes” when `popular` is non-empty, then an `optgroup` “All makes” for every catalog make. Popular names therefore appear in both groups. “All makes” is the full catalog, which is the “every brand” section.

**Missing:** Nothing the statement requires. The source does not name which brands are major; the code uses `POPULAR_MAKES`. The section labels are “Popular makes” and “All makes”. The Autotrader screenshots are not in the repository, so the visual match to those pictures was not checked. If the catalog request fails, `makeOptions` stays empty and Make (and Model) become free-text inputs instead of the grouped select. That path has no two-section dropdown.
