# Implementation check: CR-005 through CR-008

Thread 2 of 20. Read-only check of the active .NET 10 backend (`DealerOps.Core`, `DealerOps.Gateway`) and `frontend/react`. `DealerOps.AiService` was not opened; these four items do not call it. Java and Vue were not inspected.

`DealerOps.Gateway` (`backend/dotnet/DealerOps.Gateway/Program.cs`) reverse-proxies `/api/v1` to Core. It has no extra route for these four items.

No other file in `requirements/update-cr/analysis/` names CR-005 through CR-008. The inventory itself leaves two details unnamed: which sales metrics (CR-005) and which employee fields a manager may edit (CR-007).

| CR | Status | What the code does |
| --- | --- | --- |
| CR-005 | implemented | Sales report lists each active member, plus former members who sold in the period, with sold count, revenue, gross profit, open leads, and won leads. |
| CR-006 | implemented | A dealership manager can set another member of the same dealership to manager. The caller cannot change their own role. |

## CR-005

**Statement:** The client wants a list of all sales employees and their sales metrics.

**Status:** implemented

**Place named:** None. The sentence follows the sales-report period options and the dashboard sales section. It does not name a page or the metrics.

**Present:**

- `frontend/react/src/router.tsx` maps `/reports/sales-funnel` to `SalesFunnelPage` behind `DealerGuard`, so any bound dealer user can open it. `AppLayout` labels that route "Sales report".
- `SalesFunnelPage` renders a table (`aria-label` "Sales by salesperson") with columns Salesperson, Vehicles sold, Revenue, Gross profit, Open leads, and Won leads. An empty list shows "No sales employees yet." A row whose `activeMember` is false appends "(former member)".
- The page loads that table from `reportsApi.sales` (`frontend/react/src/api/reports.ts`), `GET /api/v1/vehicles/report/sales`, with the selected period (`TODAY`, `WEEK`, `MONTH`, `YEAR`). The client type is `SalespersonSales`.
- `VehicleController.SalesReport` (`backend/dotnet/DealerOps.Core/Vehicle/VehicleController.cs`) calls `VehicleService.SalesReport`. `Salespeople` builds one `SalespersonSales` per active membership of the dealership, and also per `SoldBy` username that has a sale in the period. `DealerRole` (`backend/dotnet/DealerOps.Core/Dealer/DealerRole.cs`) is only `Manager` or `Staff`; there is no sales-employee role. Vehicle counts, revenue, and gross profit come from vehicles that member sold in the period (`sold_by`). Open leads are leads they own that are not closed, with no period filter. Won leads are leads they own whose stage is `WON` and whose `UpdatedAt` is on or after the period start.
- `DashboardPage` calls the same `reportsApi.sales` and shows period totals (vehicles sold, revenue, gross profit) in the Sales section. It does not render `sales.salespeople`. A link goes to "Full sales report".

**Missing:** Nothing the statement requires. The source does not define "sales employees" or the metrics. The code treats every active member as a row, and the metrics on that row are the five columns above. The dashboard Sales section does not repeat the list; the statement does not say it must.

## CR-006

**Statement:** Manager accounts must be able to promote other staff to managers.

**Status:** implemented

**Place named:** None. The inventory groups this with manager staff actions.

**Present:**

- `frontend/react/src/router.tsx` wraps `/team` in `ManagerGuard`. A caller whose `dealerRole` is not `MANAGER` is sent to their home page. `AppLayout` adds the Team nav item only when `dealerRole === 'MANAGER'`.
- On the Members tab, `TeamPage` (`frontend/react/src/pages/TeamPage.tsx`) shows "Make manager" for another member whose `dealerRole` is not `MANAGER`. The signed-in row shows "You" and has no role button. Confirming calls `teamApi.setRole` (`frontend/react/src/api/members.ts`), `PUT /api/v1/dealer/members/{username}/role` with `{ dealerRole }`.
- `DealerTeamController.SetMemberRole` (`backend/dotnet/DealerOps.Core/Dealer/DealerTeamController.cs`) calls `MembershipService.SetRoleInOwnDealership`. That method calls `TenantGuard.RequireManager` (`backend/dotnet/DealerOps.Core/Common/Tenant/TenantGuard.cs`). If the username is the caller's, it throws `FORBIDDEN` with "You cannot change your own role." Otherwise `ChangeRole` sets `MembershipEntity.DealerRole` and audits the change.
- A platform admin can do the same change from Admin > Members through `adminApi.setRole` and `AdminMemberController.SetRole` (`MembershipService.SetRole`, `TenantGuard.RequireAdmin`). That path is in addition to the manager path.

**Missing:** Nothing the statement requires. The same control also demotes a manager to staff ("Make staff"). The statement does not forbid that. A manager cannot change their own role, so this path cannot remove the last manager by self-demotion.

## CR-007

**Statement:** Manager accounts must be able to edit certain employee information.

**Status:** implemented

**Place named:** None. The inventory says the document does not list which fields.

**Present:**

- The same manager-only Team page shows Edit on every member row, including the signed-in manager. `openEdit` fills `displayName` and `phone`. The drawer labels them "Full name" and "Phone". Save calls `teamApi.update`, `PATCH /api/v1/dealer/members/{username}`, body `MemberPatchBody` (`displayName`, `phone`; a blank phone is sent as null).
- `DealerTeamController.PatchMember` calls `MembershipService.UpdateInOwnDealership`. That method requires a manager, loads the active membership in the caller's dealership, and writes `AppUserEntity.DisplayName` and `AppUserEntity.Phone`. A phone that belongs to another account throws `PHONE_TAKEN`. An unchanged body returns without writing. The change is audited as `APP_USER` / `UPDATE`.
- `PatchMemberRequest` (`backend/dotnet/DealerOps.Core/Dealer/Dto/PatchMemberRequest.cs`) is full name (required, max 120) and phone (optional, max 40). Its comment states those are the fields a dealership manager may edit.

**Missing:** Nothing the statement requires. The source says "certain" and does not name fields. The manager edit is full name and phone only. Email and username are not on `PatchMemberRequest`. A platform admin edits email and phone separately through `MembershipService.UpdateContact` (`AdminMemberController.UpdateContact`); that is not the manager path.

## CR-008

**Statement:** The members section must include a column for when the member joined.

**Status:** implemented

**Place named:** None in the sentence. The inventory places it with the manager staff actions. A later sortable-column note (CR-013) says Team > Members includes "Date Added (when added)" and says the document does not explicitly equate that label with this column.

**Present:**

- `TeamPage` Members table columns are Member, Username, Role, Source, Joined, and Actions. Joined is a `SortableTh` with `sortKey` `joinedAt`. The cell is `dateTimeLocal(m.joinedAt)`.
- `MemberOption.joinedAt` in `frontend/react/src/api/members.ts` is documented as when the membership was created, UTC. `membersApi.list` loads `GET /api/v1/members`.
- `MemberDirectoryController.List` (`backend/dotnet/DealerOps.Core/Dealer/MemberDirectoryController.cs`) returns `MemberDirectoryService.ActiveMembers`. That method selects active memberships of the caller's dealership and sets `MemberOption.JoinedAt` from `MembershipEntity.CreatedAt` (`backend/dotnet/DealerOps.Core/Dealer/Dto/MemberOption.cs`: "When the membership row was created (UTC)").
- `AppDbContext.ApplyTimestamps` sets `CreatedAt` to UTC now when the membership entity is `Added`. `JoinRequestService.Approve` and the first-manager bind in `MembershipService` insert a new `MembershipEntity` without assigning `CreatedAt` themselves, so the timestamp hook supplies it. A later update of an existing membership row does not change `CreatedAt`.

**Missing:** Nothing the statement requires for Team > Members. The column header is "Joined", not "Date Added". The platform-admin Members tab (`AdminPage`, columns Username, Dealership, Role, Contact, Sign-in, Status, Password, Change role, Account) has no join date, and `MemberResponse` has no joined field. That tab is a different members list; this sentence sits with the manager staff actions, and the Team page is the members section that has the column.
