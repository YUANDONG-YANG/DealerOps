# Implementation check: CR-048 through CR-050

Checked against the active .NET backend (`DealerOps.Core`, `DealerOps.Gateway`) and `frontend/react`. Java and Vue were not used. Notes in `requirements/update-cr/analysis/` that describe an optional any-http(s) Carfax URL, a sell body of date and price only, and a DMS drawer with no leads are older than the symbols below.

| CR | Status | What the code does |
| --- | --- | --- |
| CR-048 | partial | A non-empty Carfax URL must be https on carfax.com or carfax.ca before save. The same URL is not exclusive across vehicles, and a blank URL still saves. |
| CR-049 | implemented | A sale is refused without a CRM customer or Other plus a typed buyer name. Other is stored as `soldToName` and does not create a customer link. |
| CR-050 | implemented | The DMS vehicle drawer lists that vehicle's leads. The inventory table also has a Leads count column. The count column is the optional part of this CR. |

## CR-048

**Statement:** The DMS Carfax URL must be exclusive and must be a real Carfax link before the record can be saved.

**Status:** partial

**Present:** On the DMS vehicle form, Carfax URL is optional (`purchaseFields`, `required: false`). `validateForm` rejects a non-empty value longer than 500 characters, and rejects a changed value that fails `isCarfaxUrl`. That helper accepts only `https` whose host is `carfax.com`, `carfax.ca`, or a subdomain of either. A value that passes is shown as **Open Carfax report**. An unchanged stored URL is not re-checked, so a row saved before this rule can still be edited. `vehiclesApi` sends an empty string as `null`.

`VehicleService.Create` calls `RequireCarfaxLink` before insert. `VehicleService.Patch` calls it only when `carfaxUrl` is in the changed set. `RequireCarfaxLink` returns immediately for null or whitespace. Otherwise the value must be an absolute `https` URI and `IsCarfaxHost` must accept the host (`carfax.com`, `carfax.ca`, or a subdomain). Failure is `400` `VALIDATION` with `fieldErrors.carfaxUrl` and the message `Carfax URL must be an https link on carfax.com or carfax.ca.` There is no call to a Carfax product API. `vhr.carfax.ca` matches the subdomain rule. `CreateVehicleRequest` and `PatchVehicleRequest` still annotate `CarfaxUrl` with a pattern that allows any http(s) URL; the host check runs after that annotation. `dealer-platform/openapi.yaml` uses the same loose pattern and describes the stricter https host rule.

The gateway route `dealer-core-public` forwards `/api/v1/{**catch-all}` to Core. It does not add a Carfax rule.

**Missing:** Nothing makes one Carfax URL exclusive to one vehicle. `VehicleEntity.CarfaxUrl` is a nullable 500-character column. `AppDbContext.ConfigureVehicle` unique-indexes `(DealerId, Vin)` only (`uk_vehicle_vin`). Stock numbers have `RequireUniqueStockNumber`; Carfax URLs do not. Two vehicles can store the same link. A blank URL still saves on the form and on create.

The analysis folder does not settle the word exclusive. `07-workflows-and-ui.md` (W20) says it is undefined (one URL per vehicle, or only Carfax hosts). `08-api-and-integrations.md` §2.5 treats exclusive as rejecting non-Carfax URLs and says a uniqueness reading is not stated. `05-data-model.md` §11 and `10-design-and-code-impact.md` §16 treat exclusive as unique, in the same sense CR-046 uses for a phone that cannot be shared. The host check matches the first reading. The unique-URL reading is not in the code. Whitespace-only input is treated as absent by `RequireCarfaxLink` and would be stored if a client sent it; the DMS form rejects it.

**Opened:** `frontend/react/src/pages/DmsPage.tsx` (`validateForm`, `purchaseFields`, `mapWrite`); `frontend/react/src/vehicleRules.ts` (`isCarfaxUrl`); `frontend/react/src/api/vehicles.ts` (`vehicleWriteBody`); `backend/dotnet/DealerOps.Core/Vehicle/VehicleService.cs` (`Create`, `Patch`, `RequireCarfaxLink`, `IsCarfaxHost`); `backend/dotnet/DealerOps.Core/Vehicle/VehicleEntity.cs` (`CarfaxUrl`); `backend/dotnet/DealerOps.Core/Vehicle/Dto/CreateVehicleRequest.cs` (`CarfaxUrl`); `backend/dotnet/DealerOps.Core/Vehicle/Dto/PatchVehicleRequest.cs` (`CarfaxUrl`); `backend/dotnet/DealerOps.Core/Data/AppDbContext.cs` (`ConfigureVehicle`); `backend/dotnet/DealerOps.Gateway/appsettings.json` (route `dealer-core-public`); `dealer-platform/openapi.yaml` (`carfaxUrl` on the vehicle write schemas).

## CR-049

**Statement:** A vehicle sale must be linked to a customer, with an Other choice that lets the seller type a buyer.

**Status:** implemented

**Present:** The DMS sell dialog requires a buyer. `sell` stops with `Choose the buyer: a CRM customer or Other` when `buyerId` is empty, and with `Enter the buyer name` when Other is chosen and the name is blank. The buyer control lists CRM customers from `customersApi.list` and an option `Other (not in CRM)` (`OTHER_BUYER`). Other reveals a Buyer name field, `maxLength` 120. Confirm posts `vehiclesApi.sell` with `buyerCustomerId` set for a CRM customer, or `buyerName` set and `buyerCustomerId` null for Other.

`VehicleController.Sell` posts to `VehicleService.Sell`. After the sold-date and sold-price checks, a missing customer and a missing trimmed `BuyerName` throw `400` `VALIDATION` on `buyerName`: `Choose a customer, or Other with the buyer's name.` A `BuyerCustomerId` must be a customer of this dealership, or the call fails on `buyerCustomerId`. When a customer is chosen and the vehicle has no owner link, the same transaction inserts `CustomerVehicleEntity`. When Other is chosen, `SoldToName` stores the typed name and no customer link is created. `SellVehicleRequest.BuyerName` is at most 120 characters. The DMS Sold to column shows `linkedCustomer.name` or `soldToName`.

If the vehicle is already linked, the dialog shows that customer's name and does not offer Other. `beginSell` sets `buyerId` to that customer. Selling to a different customer, or to Other while a link exists, returns `409` `VEHICLE_ALREADY_LINKED` (`This vehicle is linked to another customer. Choose that customer or unlink first.`). The sale is still tied to a customer.

`dealer-platform/openapi.yaml` `sellVehicle` documents the same buyer rule. The gateway catch-all proxies `POST /api/v1/vehicles/{id}/sell` to Core.

**Missing:** Nothing the sentence requires. The document does not name the stored fields. The code uses `buyerCustomerId` or `buyerName` / `soldToName`. Other is not offered when a customer is already linked; that sale uses the linked customer. A typed Other buyer is not a CRM row.

**Opened:** `frontend/react/src/pages/DmsPage.tsx` (`OTHER_BUYER`, `beginSell`, `sell`, `ConfirmDialog`, Sold to column); `frontend/react/src/api/vehicles.ts` (`vehiclesApi.sell`); `backend/dotnet/DealerOps.Core/Vehicle/VehicleController.cs` (`Sell`); `backend/dotnet/DealerOps.Core/Vehicle/VehicleService.cs` (`Sell`); `backend/dotnet/DealerOps.Core/Vehicle/Dto/SellVehicleRequest.cs` (`SellVehicleRequest`); `backend/dotnet/DealerOps.Core/Vehicle/VehicleEntity.cs` (`SoldToName`); `backend/dotnet/DealerOps.Core/Vehicle/Dto/VehicleResponse.cs` (`SoldToName`, `LinkedCustomer`); `dealer-platform/openapi.yaml` (`sellVehicle`, `VehicleSell`).

## CR-050

**Statement:** Vehicle information in DMS should include the vehicle's leads, and might include a column for how many leads the vehicle has.

**Status:** implemented

**Present:** The required part is the vehicle's leads on DMS vehicle information. The count column is marked possible in the inventory, not required. Both are in the code.

The DMS edit drawer renders `VehicleLeadsPanel` for a saved vehicle (`edit.id`). The panel calls `leadsApi.list({ vehicleId, page, size: 10 })`. Each row links to `/leads?leadId=` and shows customer name, stage, owner, and follow-up (or `not needed` when the stage is won or lost). An empty result says `No leads for this vehicle.` `LeadController.List` accepts `vehicleId` and `LeadService.List` keeps leads with that `VehicleId` for the current dealership, any stage. `LeadListItem` supplies `CustomerName`, `Stage`, `OwnerUsername`, and `NextFollowUpOn`.

The inventory table has a sortable Leads column bound to `leadCount`. `VehicleService.List` projects each row with `ToResponse`, which sets `LeadCount` to the count of leads on that vehicle and dealer, open or closed. Sort field `leadCount` orders by the same count. `VehicleResponse.LeadCount` and `listVehicles` / the vehicle schema in `dealer-platform/openapi.yaml` expose it. `listLeads` documents query `vehicleId` as only leads on this vehicle.

The add-vehicle form has no id yet, so the panel appears after the vehicle exists. The gateway catch-all proxies both `GET /api/v1/vehicles` and `GET /api/v1/leads`.

**Missing:** Nothing the sentence requires. The document does not say whether the count is open leads only; the code counts every stage. It does not specify empty copy; the panel has one. CRM has its own `leadCount` column; that is a customer list, not this DMS request.

**Opened:** `frontend/react/src/pages/DmsPage.tsx` (`columns` `leadCount`, `VehicleLeadsPanel`); `frontend/react/src/components/VehicleLeadsPanel.tsx` (`VehicleLeadsPanel`); `frontend/react/src/api/leads.ts` (`leadsApi.list`, `LeadFilters`); `backend/dotnet/DealerOps.Core/Lead/LeadController.cs` (`List`); `backend/dotnet/DealerOps.Core/Lead/LeadService.cs` (`List`); `backend/dotnet/DealerOps.Core/Lead/Dto/LeadListItem.cs` (`LeadListItem`); `backend/dotnet/DealerOps.Core/Vehicle/VehicleService.cs` (`List`, `Sorted`, `ToResponse`); `backend/dotnet/DealerOps.Core/Vehicle/Dto/VehicleResponse.cs` (`LeadCount`); `dealer-platform/openapi.yaml` (`listLeads` `vehicleId`, `listVehicles` sort `leadCount`, `Vehicle` `leadCount`).
