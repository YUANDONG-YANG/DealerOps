# Functional cases: authentication and tenancy

Current stack only: `DealerOps.Gateway` and `DealerOps.Core`. The browser calls the gateway. These cases do not target the retired Java service or call Core directly.

Sources: `design/14-Backend-API-Contract.md` §1.2–§1.4 and §2, `design/15-Data-Auth-and-Gateway.md` §2 and §8, `dealer-platform/openapi.yaml` (`/api/v1/auth/login`, `/api/v1/me`, `/api/v1/vehicles/{id}`), `backend/dotnet/DealerOps.Core/Dealer/AuthController.cs`, `backend/dotnet/DealerOps.Gateway/Program.cs`, `backend/dotnet/DealerOps.Core/Common/Tenant/TenantMiddleware.cs`, `backend/dotnet/DealerOps.Core/Vehicle/VehicleService.cs`.

| AUTH-01 | `POST /api/v1/auth/login` accepts an email, username, or phone plus a password and returns a DealerOps session (`design/14-Backend-API-Contract.md` §1.4; `LoginResponse`). | black-box | Gateway is the only entry. An active account with a password hash exists. The executor knows one sign-in name and its password; neither value is recorded here. | `POST /api/v1/auth/login` with `Content-Type: application/json` and body `{"identifier":"<known-identifier>","password":"<known-password>"}`. Send no `Authorization` header. | HTTP 200 JSON with `accessToken` (non-empty string), `role` (`Platform.Admin` or `Dealer.User`), and `displayName` (string). The token is an HS256 JWT with `sub` (username), `name`, and `roles`. Record the shape only, not the token. | not executed; gateway not observed | NOT RUN |
| AUTH-02 | A login request with no identifier is a validation failure, not a credential failure (`design/14-Backend-API-Contract.md` §1.4; `LoginRequest` `[Required]`; Core invalid-model factory). | negative | Gateway is the only entry. No bearer token. | `POST /api/v1/auth/login` with `Content-Type: application/json` and body `{"password":"<non-blank>"}`. Omit `identifier`. | HTTP 400. | AUTH-03 | An unknown sign-in name and a wrong password return one message so the caller cannot tell them apart (`design/14-Backend-API-Contract.md` §1.4; `AuthService.Login`). The same message is specified for an inactive account. | negative | Gateway is the only entry. One known active password account exists. Its password is not recorded here. | 1. `POST /api/v1/auth/login` with `{"identifier":"not-a-real-account","password":"<unused>"}`. 2. Repeat with the known identifier and a password that is not that account's password. | Each response is HTTP 401. Body `code` is `UNAUTHORIZED` and `message` is `Invalid sign-in name or password`. The two bodies do not name a different reason. Not HTTP 200. | not executed; gateway not observed | NOT RUN |
| AUTH-04 | A protected `/api/v1` route without a DealerOps JWT is rejected at the gateway (`design/14-Backend-API-Contract.md` §1.2–§1.3; gateway role gate). Anonymous exceptions are `POST /api/v1/auth/login`, `register`, `google`, `firebase`, `GET /api/v1/catalog/**`, and `GET`/`POST /api/v1/public/**`. | security boundary | Gateway is the only entry. The caller has no `Authorization` header. This application does not use a cookie session. | `GET /api/v1/me` and `GET /api/v1/vehicles`, each with no `Authorization` header. | Each response is HTTP 401. Body is `code` `UNAUTHORIZED` and `message` `Unauthorized`, written by the gateway before Core. A gateway-authored error has `code` and `message` only. | not executed; gateway not observed | NOT RUN |
| AUTH-05 | A presented bearer token that is not a valid DealerOps JWT does not authenticate (`design/14-Backend-API-Contract.md` §1.3; gateway JWT events and role gate). | security boundary | Gateway is the only entry. | `GET /api/v1/me` with `Authorization: Bearer not-a-jwt`. | HTTP 401. Body `code` is `UNAUTHORIZED` and `message` is `Unauthorized`. Not HTTP 200. | not executed; gateway not observed | NOT RUN |
| AUTH-06 | A vehicle id owned by another dealership is hidden. The response is not found, not forbidden (`design/14-Backend-API-Contract.md` §1.3; `GET /api/v1/vehicles/{id}`; `VehicleService.LoadThisDealer`). Tenant authority is the one active membership row, not a client id (`design/15-Data-Auth-and-Gateway.md` §2). | security boundary | Two active dealerships, A and B. A `Dealer.User` has exactly one active membership, in A. A vehicle id exists only in B. A bearer token for that user was issued by AUTH-01 and is not recorded here. | `GET /api/v1/vehicles/{id-owned-by-B}` with `Authorization: Bearer <token-for-A>`. Do not send a dealership id as the tenant. | HTTP 404. Body `code` is `NOT_FOUND` and `message` is `Not found`. The body does not include that vehicle's fields. Not HTTP 403 and not HTTP 200. | not executed; gateway not observed | NOT RUN |
| AUTH-07 | A client `dealerId` query value is ignored. The vehicle list stays inside the caller's membership dealership (`design/14-Backend-API-Contract.md` §1.3; `TenantMiddleware` sets the tenant from membership; vehicle query filter). | security boundary | Same caller and dealerships as AUTH-06. At least one vehicle id is known to exist only in B. | `GET /api/v1/vehicles?dealerId=<B>` with `Authorization: Bearer <token-for-A>`. | HTTP 200. The page does not contain the vehicle id known to belong only to B. `VehicleResponse` has no `dealerId` field, so isolation is the absence of B's ids. The query value does not change the tenant. | not executed; gateway not observed | NOT RUN |
| AUTH-08 | A `Dealer.User` with no active membership may read their own account and is forbidden on business routes (`design/14-Backend-API-Contract.md` §1.3 and §2; `TenantMiddleware`). | security boundary | An active `Dealer.User` has zero `membership.active=1` rows. A bearer token for that user is not recorded here. | 1. `GET /api/v1/me` with that bearer token. 2. `GET /api/v1/vehicles` with the same token. | Step 1 is HTTP 200, `role` is `Dealer.User`, and no dealership id is returned (`dealerId` is null and Core omits null JSON properties). Step 2 is HTTP 403, `code` `FORBIDDEN`, `message` `Forbidden`, from Core (a `requestId` may be present). Step 2 is not HTTP 401 and not HTTP 404. | not executed; gateway not observed | NOT RUN |
| AUTH-09 | `Platform.Admin` cannot read business data. Business URLs are forbidden for that role (`design/14-Backend-API-Contract.md` §1.3; gateway role gate). | security boundary | A `Platform.Admin` password-login token from AUTH-01, `role` `Platform.Admin`. The token is not recorded here. | `GET /api/v1/vehicles` with `Authorization: Bearer <admin-token>`. | HTTP 403. Body `code` is `FORBIDDEN` and `message` is `Forbidden`, written by the gateway before Core, so the body has `code` and `message` only.
