| INV-01 | DMS-06, DMS-07. A bound dealer user lists this dealership's vehicles, 10 per page, newest first, and can filter the list. | `Dealer.User` with a dealership id. React `DealerGuard` allows both `MANAGER` and `STAFF`. `Platform.Admin` is not this actor. | 1. Sign in as a bound dealer user and open `/dms`. 2. The page loads `GET /api/v1/vehicles` through the gateway with `page=0` and `size=10` (`vehiclesApi.list`). 3. Set Status to In stock (`status=IN_STOCK`). Make, model, year, condition, and body type are separate controls. 4. Type a keyword and wait 350 ms, or press Search. The client sends `q` only when it is non-empty, and omits blank filters. Filters that are sent are combined. | `VehicleController.List` calls `VehicleService.List`. The query is limited to the caller's dealership and to rows with `DeletedAt == null` (`AppDbContext` vehicle query filter). `status`, `condition`, `bodyType`, and `modelYear` are exact matches. `make` and `model` are exact and case-insensitive. `q` is a substring of VIN, make, model, or stock number. Sort is `createdAt` descending, then `id` descending. The JSON body is `{ items, page, size, totalElements }` with `page` 0 and `size` 10. The DMS table renders those items. An empty `items` array shows "No vehicles match." A list response with code `FORBIDDEN` shows "You do not have access to DMS." | Not observed. No gateway or React listener was up, and no list response was received. Item count, stock numbers, VINs, and the HTTP status were not read. | NOT RUN |
| INV-02 | DMS-01, DMS-04. Create accepts a vehicle only when the required intake fields pass the rules in `CreateVehicleRequest` and `VehicleService.Create`. Omitting `source` is rejected and does not insert a row. | `Dealer.User` bound to a dealership (`TenantGuard.RequireTenantId`). The DMS Add vehicle form uses the same required set. | 1. As that user, `POST /api/v1/vehicles` with `Content-Type: application/json`. 2. Include make, model, model year, VIN, purchase cost, date added, and condition. Omit `source`. 3. Do not copy a VIN into this record; this session did not send a body. 4. On the React form, leave Source unset and submit Add vehicle. | Core model validation runs before `VehicleService.Create`. `CreateVehicleRequest.Source` is `[Required(ErrorMessage = "Vehicle source is required.")]`. `InvalidModelStateResponseFactory` returns HTTP 400, `code` `VALIDATION`, `message` `Validation failed.`, and `fieldErrors.source` = `Vehicle source is required.` No vehicle row is inserted. The React `validateForm` sets `source` to `Required` and returns before `vehiclesApi.create`, so the drawer does not call the API for a blank source. A body that does pass validation is stored by `Create` as `IN_STOCK`, with the VIN upper-cased, make and model trimmed, and `bodyType` `OTHER` when omitted. That success path was not executed. | Not observed. The POST was not sent, and the Add vehicle form was not submitted. No response body or status code was seen. | NOT RUN |
| INV-03 | Contract §4: a platform admin calling a vehicle URL receives `403` `FORBIDDEN` and no inventory fields. Gateway role gate (AUTH-08) enforces this before core. | `Platform.Admin`. | 1. In the React app, sign in as that admin and open `/dms`. | The gateway role gate, for an authenticated `Platform.Admin` whose path is under `/api/v1` and is not `/api/v1/admin`, `/api/v1/me`, or `/api/v1/auth`, writes HTTP 403 and `{ "code": "FORBIDDEN", "message": "Forbidden" }`. The handler returns before the request is proxied, so the body has no vehicle fields. On the web app, `DealerGuard` requires `role === Dealer.User` and a dealership id; a platform admin is sent to `/admin` and `DmsPage` is not rendered. | Not observed. No admin token was presented and no response was received. The 403 above is the status the gateway source assigns; it was not seen on the wire. | NOT RUN |
