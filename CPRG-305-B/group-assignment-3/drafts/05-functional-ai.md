# Functional cases: dealer assistant

The dealer assistant on the current .NET path. The browser talks only to DealerOps.Gateway. Gateway forwards `POST /api/v1/assistant/ask` to DealerOps.Core. Core retrieves this dealership's records and, when a summary is required, calls DealerOps.AiService at `POST /internal/v1/assistant`. DealerOps.AiService does not access the database.

Case IDs in the table are execution IDs. They are not the requirement IDs in `design/`.

## What this product implements

| Hop | Where it lives | What it does |
|---|---|---|
| Browser | `frontend/react/src/components/AssistantWidget.tsx` on signed-in dealer pages (a panel, not its own route) | Sends `{ "text" }` through `frontend/react/src/api/assistant.ts` |
| Gateway | `backend/dotnet/DealerOps.Gateway` route `dealer-core-public` | Accepts `/api/v1/**` for Core. `/internal/v1/**` is not a browser route |
| Core | `backend/dotnet/DealerOps.Core/Assistant/AssistantService.cs` and `AssistantResourceQuery.cs` | Tenant comes from the signed-in membership. Retrieval and counts stay in Core |
| AiService | `backend/dotnet/DealerOps.AiService` `POST /internal/v1/assistant` | Summarizes the resource cards Core already sent. No database client |

Contract: `design/14-Backend-API-Contract.md` §10 and §11, and `design/AI-PROTOCOL-AND-RULES.md` §B.3. Acceptance shape: `design/16-Acceptance-and-Test.md` BE-12 and BE-14. UI copy: `design/13-Frontend-Engineering.md` (Ask row and the assistant states).

Core's outbound client is `backend/dotnet/DealerOps.Core/Integration/AiGatewayClient.cs`. Its base address is `AiService:BaseUrl` from `backend/dotnet/DealerOps.Core/appsettings.json` (`http://127.0.0.1:8082` in that file), path `/internal/v1/assistant`, with the internal credential header. That call is server-side. The browser is not on that hop.

`design/10-Web-AI-Assistant.md` describes the earlier in-store flow. These cases follow the current .NET path above.
