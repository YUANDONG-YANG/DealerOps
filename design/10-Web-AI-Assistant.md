# In-store assistant (reuse the GitHub component; keep it thin)

Version v6.1 · 2026-09-21

Do not rewrite a conversation engine. Vue only provides the input box and result cards; replies are generated by the GitHub AI assistant library after `dealer-core` filters the payload for the model.

## What the user sees

Dealer users have an Assistant page in the back office. They ask one question and get a short explanation plus links into this dealership’s resources. Examples: “Which Toyota vehicles are in stock here” and “Why can this vehicle not be listed.”

Platform administrators do not have this page. Queries are this dealership only. Phone, email, and home address are not sent to the model.

## Flow

1. Vue → Gateway → core. core recognizes the JWT and `dealer_id`.
2. core uses ordinary queries to find at most 5 of this dealership’s vehicles / customer IDs / advertisement statuses.
3. core calls ai-service via the Gateway; ai-service calls the GitHub component.
4. core verifies that any IDs returned by the model are among those 5, then builds cards. Invented paths are dropped.
5. Conversation must not change vehicles, customers, or check results.

One Q&A completes synchronously. No queue, no vector store, no complex multi-turn storage (at most the last 3 already-filtered sentences for this dealership). If the model is down, show only the retrieval list and state “Smart explanation is temporarily unavailable.”
