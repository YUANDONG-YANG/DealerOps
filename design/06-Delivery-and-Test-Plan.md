# 三人实施与测试计划

## 工作量基线

按 10 周、3 人、每人每周约 9 小时计算，总计约 270 人时：约 220 人时实现与常规测试，50 人时留给联调、缺陷、报告和演示。这是估算，不是学校规定或交付保证。

若实际只有每人每周 6 小时，总量约 180 人时，应缩小工单和统计的表现形式，并重新核对 AI 与课程交付要求；不能原样承诺 270 人时范围。

## 三人职责

### A：B/C 端体验与车辆管理，约 70 人时

负责 Vue 工程和布局、登录界面、车辆列表/详情/表单、库存相关 Java API、C 端列表/详情，以及主要响应式样式。与 C 对接咨询入口，与 B 对接广告组件。

工作包：A1 页面骨架和登录 12h；A2 车辆前后端 24h；A3 C 端展示 16h；A4 仪表板页面和交互收尾 10h；A5 关联测试及接口文档 8h。

### B：后端公共基础与广告检查，约 72 人时

负责 Java 工程、数据库迁移基础、session 权限、广告编辑页和 API、固定规则、一个真实 AI 适配器、经理复核与发布流程。

工作包：B1 工程/认证/迁移基础 14h；B2 广告前后端及版本失效 18h；B3 固定规则与 AI 24h；B4 发布事务与历史 8h；B5 相关测试及文档 8h。

### C：工单、CRM 与成交闭环，约 78 人时

负责工单前后端、咨询提交、客户/线索/跟进页面和 API、销售事务及销售页面、统计查询。

工作包：C1 简单整备工单 12h；C2 CRM 和咨询 26h；C3 成交事务和页面 20h；C4 统计查询 6h；C5 相关测试及文档 14h。

每人都有前端、后端和测试贡献，避免全部后台压给一个人。B 定义公共基础不等于替所有模块写后端。C 的事务工作由 A 评审，B 的发布规则由 C 评审，A 的接口和页面由 B 评审。

保留的 50h 由三人共同承担；若 C 提前落后，A 接销售只读列表，B 接统计查询，不新增功能。

## 相对周排期

### 第 1 周：确认与准备

三人确认本设计、评分表、实际时间和 B/C 端范围；项目方确认规则边界，取得或自建去标识样例；确定 AI 服务与调用上限。组员统一 Java/MySQL/Node 环境版本，准备仓库和接口讨论。

完成标准：范围可说明、字段和状态无分歧、AI 是否可用已明确。不应等到第 8 周才发现无法使用模型服务。

### 第 2 周：基础骨架

A 建前端布局及登录；B 建认证、迁移和种子账号；C 建工单/CRM 数据结构与接口样例。只完成一个可运行的本地实例。

完成标准：员工登录后可新增并刷新查看一辆车，未授权接口被拒绝。

### 第 3 周：库存与整备

A 完成库存，C 完成工单与可售门槛，B 实现广告草稿、固定模板和 contentVersion。

完成标准：有工单无法可售；完成整备后能准备广告；当前广告修改影响版本。

### 第 4 周：发布前检查

B 完成固定规则、mock 和真实 AI 最小调用；A 接 C 端展示；C 接访客咨询与线索列表。

完成标准：一条阻断样例、一条正常样例、一次真实 AI 请求可展示。真实服务受限时及时与项目方调整验收，不能隐藏问题。

### 第 5 周：B/C 端连通

经理检查并发布车辆，C 端能浏览和咨询，B 端可以分配和记录跟进。补版本冲突和 AI 降级。

完成标准：从入库到咨询跟进完整走通；第 5 周以前必须联调，不允许三人各写一整学期最后拼接。

### 第 6 周：成交闭环

C 实现成交事务，A 做仪表板，B 协助审计和接口一致性。

完成标准：成交后自动下架、线索关闭、统计更新；两次并发成交最多成功一次。

### 第 7 周：异常与 AI 评估

三人按所属模块完成关键自动测试、24 条检查样例评估、权限和失效检查测试。

完成标准：核心验收案例通过，已知缺陷有负责人；停止增加功能。

### 第 8 周：演示环境

配置单实例和 MySQL 持久化，准备可复现启动步骤、备份恢复、虚构演示数据。云环境可用时使用 HTTPS；否则完成本地演示包并如实说明部署范围。

### 第 9 周：报告与答辩

整理业务流程图、ER 图、接口、测试证据、AI 结果和个人贡献。录制一次完整备用演示，准备正常与断网两条路径。

### 第 10 周：缓冲

修复影响演示的缺陷、最后回归和排练。不要加入图片增强、支付或第三方发布。

## 验收用例

以下是计划，当前没有应用代码，因此未执行，也不标记为通过。

1. T01：有效登录、错误密码、退出后访问后台；预期成功/401/401。
2. T02：Visitor 读 CRM、Staff 发发布和成交请求；预期 401 或 403，无数据改变。
3. T03：新增车辆，刷新，重复 VIN/stock number；预期持久化，重复 409。
4. T04：负价格、非法里程、过长描述及未知 photoKey；预期 400；零必收费用可保存。
5. T05：存在进行中工单时经理标可售；预期 409；工单完成后成功。
6. T06：AVAILABLE 新建工单被拒绝；回整备会下架并使检查失效，再允许工单。
7. T07：规则边界样例；预期与固定规则 ID 一致，价格使用十进制。
8. T08：真实 AI、超时、无效 JSON；预期 SUCCESS/UNAVAILABLE/INVALID_RESPONSE，失败不显示成功。
9. T09：广告内提示注入及伪造 quote；预期无工具动作，错误证据被过滤或结果无效。
10. T10：检查过程中改稿；预期 check 针对旧快照，stale=true，不能发布新稿。
11. T11：未检查、有 BLOCK、旧版本发布；预期 409；Staff 即使构造请求也不能发布。
12. T12：AI 提示未确认/降级未确认/缺 reviewNote；预期 400 或 409；正确经理复核可发布。
13. T13：已发布车辆改价；预期同事务回 DRAFT，C 端不可见；重查并发布才恢复。
14. T14：C 端咨询；预期一条 customer + lead；后台能查看和跟进，无自动发送消息。
15. T15：同 submissionKey 重试和并发提交；预期最多一条客户/线索，响应不泄露已有记录。
16. T16：C 端读已下架车辆或咨询已售车辆；预期详情 404、咨询 409；公共 API 无 PII。
17. T17：经理登记成交；预期一条 sale、SOLD/CLOSED/WON、其他 open leads LOST、跟进日期清除。
18. T18：两个并发成交请求；预期最多一个成功，sale.vehicle_id 唯一，无部分更新。
19. T19：成交中途故障注入；预期整体回滚，无 WON 但车辆仍可售等半成品状态。
20. T20：成交前后及月份边界核对统计；预期按 Toronto 月份计算，成交额等于销售记录合计。
21. T21：停用用户、CSRF 缺失、咨询限流；预期 403/403/429，无越权副作用。
22. T22：两人同时修改/陈旧页面状态操作；预期 409，输入保留，不能覆盖最新记录。
23. T23：应用重启与数据库备份恢复；预期业务数据保留，session 可失效并重新登录。
24. T24：桌面 B 端、手机 C 端、空列表、加载错误、键盘表单；预期可操作且无关键遮挡。

## 自动化测试范围

JUnit 做价格和状态规则单元测试；Spring Boot + 真实 MySQL 测试实例验证事务、外键和并发。不要只用 H2 代替 MySQL 来证明行锁行为。

API 集成测试覆盖越权、检查失效、重复咨询及成交回滚。浏览器自动化只保留一个完整业务主流程和一个改价后拦截流程；其余界面按验收表人工检查，避免三人团队被大量低价值 UI 测试拖住。

AI 在线评估与离线测试分开。自动测试默认不调用付费服务；真实评估手动触发，记录调用数、耗时和使用服务提供的计费信息；未知费用不得写成 0。

## 演示数据与 8 分钟脚本

准备 1 个经理、2 个员工，6 辆虚构车辆、3 张工单、8 条线索，包含一辆整备中、一辆已有公开广告、一辆已售。图片只用许可明确的演示素材或本项目预置占位图，不复制真实客户照片。种子数据不写真实联系方式。

1. 0:00–1:00：说明单店 B/C 端，新增或打开 DEMO-001 整备中车辆。
2. 1:00–2:00：展示未完成工单的限制，完成工单，经理标可售。
3. 2:00–3:30：广告检查，展示一项可修复问题，修改后重查；展示真实 AI 建议与经理复核。
4. 3:30–4:30：发布，打开 C 端车辆详情，用虚构资料提交咨询。
5. 4:30–5:30：回 B 端查看线索、分配、记跟进。
6. 5:30–6:30：登记成交，显示车辆售出、广告下架、其他线索自动关闭。
7. 6:30–7:30：刷新 C 端和 Dashboard，验证结果一致。
8. 7:30–8:00：展示一条 AI 不可用或旧审核拦截，说明限制与后续改进。

种子重置仅开发/演示环境可执行，必须明确目标数据库，不开放给 C 端或普通员工。正式演示前准备数据库备份、录屏和故障降级说明。
