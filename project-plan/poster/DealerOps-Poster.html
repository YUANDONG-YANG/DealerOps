The problem

Small dealerships coordinate inventory, customers, sales, advertising checks, and reconditioning across disconnected tools. Staff need one place to work while keeping each dealership's records private.

Shared access creates risk: a user may see another store's data, edit a sold vehicle, or export an ad check that no longer reflects current vehicle details.

What we built

DealerOps brings dealership operations into one browser application. It combines inventory management, CRM, lead follow-up, work orders, ad compliance, audit history, reporting, and a read-only AI assistant.

How it works

01 · Sign inAuthenticate; gateway validates JWT; core checks role and dealership membership.
02 · WorkCreate or update inventory, customer, lead, or work order through the gateway.
03 · EnforceCore applies tenant and business rules, then records changes in MySQL.
04 · ReviewUse audit, dashboards, ad checks, and read-only assistant for follow-up.

Security by design

  • Dealership records are tenant-scoped.
  • Only the gateway is exposed to the browser.
  • Passwords use BCrypt; JWT carries the authenticated identity.
  • Role and membership checks run in the core.
  • Business changes and sign-in attempts are audited.
  • AI assistant answers questions without database writes.

Delivery decisions

  • Moved to the active .NET 10 and React stack; Java and Vue are retired.
  • Azure Linux App Service and Terraform provide the deployed hosting path.
  • MySQL remains the only application database.
  • External marketplace publishing is simulated; no live partner API access.
  • Card payment processing, OCR, queues, and a second database are not built.
Scope boundary: payment ledger and bill-of-sale workflow exist; they do not process cards.

Engineering challenges and response

Tenant isolationEvery business workflow must respect dealership membership. Core-side authorization applies tenant checks at the service boundary.
One browser entryRouting all browser API traffic through the gateway keeps internal service routes and credentials server-side.
Data freshnessAd checks can become stale after a vehicle change. Export requires a passed, current check.
Scope disciplineLive marketplace and card services need external access. The delivered flows describe simulation and ledger boundaries clearly.
