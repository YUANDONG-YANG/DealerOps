Summary of activities

This was a setup week ahead of Sprint 1, and the plan was to lock down the foundation decisions — authentication, hosting, and the engineering ground rules — before any feature work started. We got through all three, though not the way I expected: most of the capacity went into undoing an authentication choice rather than building on it. Three working days, one contributor, and a late pivot that was better caught now than mid-sprint.

1

Authentication moved back to the client-specified model

The design had been carrying Microsoft Entra federated sign-in. Re-reading it against the written client specification, it was clear the client had actually asked for dealership accounts that the platform issues and controls itself. So we reversed it: the design went back to admin-issued username/password, the implementation followed, and a documentation sweep removed the stale Entra references so nobody on the team would be working from the old assumption later (4a24836, b546a7e).

Two earlier commits that week (d26da40, 495a1b9) were still trying to make Entra viable — a personal Microsoft account workaround and keeping Security Defaults with Authenticator MFA. Those were the dead ends that forced the decision, not leftovers from it.

2

Hosting narrowed to a single demo path

We had three half-working options and no clear answer. Cloudflare became the DevOps and demo path, Azure stayed as the backup, and the automatic Railway deploys were dropped (a208c7e). The practical constraint behind this is that the Azure student VM is currently the only demo host the team actually has access to, so the plan now matches what we can run.

3

Engineering ground rules and review material in place

Code-review notes, architecture diagrams, and a shared agent rule set went into the repo, with the same standing rules applied across the three coding tools the team uses so everyone works to one standard (5b1ce86). Setup and reuse notes were moved out of the repository root, and requirements verification was realigned with the corrected workflows (fe79a00).

What was delivered

  • Platform-issued username/password authentication — design, implementation, and docs all brought into line in the same week — in place of Entra.
  • One documented hosting path (Cloudflare for the demo, Azure in reserve) instead of three unfinished ones.
  • A single shared rule set governing the coding tools used on the project.

Impediments and how they were handled

Prior-week Entra work was sunk cost

Sign-in hardening, app-registration docs, and MFA setup all had to be written off. Root cause: a technology was chosen before it was checked against the client's written requirement. I'd rather absorb that in a setup week than discover it once sprint features depend on it, so the fix was to reverse cleanly and in one pass rather than patch around it.

A short week

Three active days, so new scope took a back seat to getting the foundation right.

What went well

The reversal landed in one pass

Because the documentation sweep went in alongside the code, no stale Entra instruction was left behind to trip up a teammate later.

The simple option held up

Choosing the specified model over the more elaborate federated-identity approach kept the auth model simple enough that it hasn't needed to change since.
